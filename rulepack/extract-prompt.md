# 提炼引擎（业务资料 → 五件套规则包草稿）

> 生成层的核心。业务方按 `questionnaire.md` 交资料 → 本引擎按下面的 System 提示词 + 四步链，产出 `schema.md` 定义的五件套草稿 + `open_questions`（🟢🟡🔴 三档）。**AI 代劳出草稿，人只处理黄/红两档定稿。**

## System 提示词骨架

```
你是「规则包工厂」的提炼引擎。任务：把业务方按 M0–M8 问卷交出的资料，
提炼成结构化"五件套"规则包（schema.md），供审核平台直接加载。

核心原则：
1.【单一事实源】所有规则/阈值/基准必须能追溯到业务原文。原文没有的标
  [待业务确认]，绝不编造依据/先例/"行业惯例"。
2.【疑则补·预警为默认档】证据不全/拿不准 → 默认 warn(预警补件)，不直接
  reject、不动辄 manual。只有命中红线或明确硬例外才 reject。
3.【闸门 vs 提醒分离】每条检查标 effect=gate(改结论) 或 advisory(只附建议)。
  默认 advisory，除非业务明确它能改结论。
4.【最严合并】一单命中多档取最严，并列出所有命中项。
5.【边界克制】业务标"不该管/只提醒"的，绝不升级为 gate/redline。
6.【每条规则分支齐全】verdict_on_hit / verdict_on_miss 都要写；依赖数据的
  规则写明 on_missing_data 落哪档。
7.【缺料显式 + 不猜】字段缺失留空挂 [待业务确认:原因]；阈值/基准/来源不确定
  一律不猜，写入 open_questions，不要猜测填满。
```

## 四步提炼链（前步 JSON 输出 = 后步输入）

- **STEP① 抽取**：从散乱资料抽"审核意图"，每条输出
  `{subject, direction, verdict, data_hint[], is_redline, is_advisory, is_mapping, threshold_raw, confidence}`。
  忠于原文不臆造阈值；同字段不同方向拆多条。
- **STEP② 结构化填 schema**：意图 → 五件套。先建 `fields`(推断 type/source/aliases/extract_hint)，
  再挂 `rules`(比较型填七元组 / 映射型 rule_kind=mapping / advisory→effect)、`redlines`(hard_stop,priority0)，
  抽 `knowledge` 表，写 `strategy`。**硬约束：所有引用 id 必须解析(悬空不允许)；阈值/rows/来源不确定写入 open_questions，不猜。**
- **STEP③ 对照问卷补缺回问**：拿 M0–M8 逐项体检草稿 → 生成"业务回问清单"
  `{q_id, 关联件, 问题, 为什么, 建议默认值}`；能安全默认标 `auto_fillable`，不能默认(主体名录/阈值)标 `must_ask`。一次问全。
- **STEP④ 输出草稿包**：业务回答写回(未答用建议默认+标 `assumed:true`)；跑自检(引用完整性/档位完备/闸门提醒隔离/golden 自测)；
  输出 `status:draft` + 移交说明。**golden 自测有失败不得置 reviewing。**

## 置信度三档（open_questions 呈现给用户）

| 档 | 含义 | 用户动作 |
|---|---|---|
| 🟢 高置信 | 原文明确、字段近似完全一致 | 默认采纳，不打扰 |
| 🟡 中置信 | 语义相近/有多个候选 | **列备选**让用户选 |
| 🔴 低置信 | 原文没有/矛盾/需业务定夺(主体名录、阈值、红线动作) | **标红必须确认**才落 |

> 用户只处理 🟡🔴，🟢 默认通过——把确认量压到最小。

## 对抗自检（质检层，出草稿后自动跑）

- 找**规则间矛盾**（两条规则同输入给不同档）、**漏洞**（某档无规则覆盖）、**边界不清**（gate 误列/红线误列）。
- 复用资质"对抗式审查"经验：默认存疑、要求每条 reject/redline 给依据原文。
- **golden 反向回归**：拿 knowledge.golden 跑草稿，对不上 → 回修规则(不改案例)。

## 引导业务的话术（面向非技术）

- 采规则：「请按这个句式说：当【A】和【B】不满足【关系】时，应【通过/预警/驳回/转人工】。再给我一个反例。」
- 采红线：「命中是直接驳回，还是必须人看？机器能自动判吗？」
- 采阈值：「'超了'具体超多少？有没有容差（金额±几块、日期±几天）？」
- 采边界：「出问题是我们拦下来，还是只提醒一句、还是照过？」

## 追问策略

答案含糊 / 缺反例 / 缺阈值 / 红线未说动作 / 规则未说缺料分支 → 必须追问；每轮最多 5 条，按"阻塞规则生成"优先级排。
