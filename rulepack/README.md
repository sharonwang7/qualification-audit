# 规则包工厂（Rule Pack Factory）

> **一句话**：规则是每个审核场景专有的（每家红线不同），但"**怎么把业务知识/审核经验变成规则包**"的方法论是通用的。工厂化 = 把"经验→规则/案例草稿"从人天降到小时级，且质量可回归。
>
> 这是「多团队复用」里最核心的护城河：新团队不用懂 regression/golden/reference，**把资料交给 AI，一键提炼出规则包草稿 + 待确认清单，人点头定稿**。

## 四个部件

| 部件 | 干什么 | 本目录文件 |
|---|---|---|
| **① 采集层** | 一套问卷 + 提示词框架，把"该写进规则包的一切"问透 | `questionnaire.md`（M0–M8） |
| **② 生成层** | 一键提炼：业务发资料 → AI 按框架产出规则包草稿（五件套） | `extract-prompt.md`（提炼引擎 + STEP①–④） |
| **③ 质检层** | 对抗自检(找矛盾/漏洞/边界不清) + 从案例提炼 golden + 业务定稿 | （见 extract-prompt §自检 + golden 回归） |
| **④ 产出** | 标准**五件套**规则包 + golden 测试集 | `schema.md`（五件套 Schema） |

## 五件套（产出物结构）

一个规则包 = 五件套，通过稳定 ID 互相引用：

1. **①字段定义 fields**：表单字段 ↔ 审核要素（含别名归一、取值来源、抽取消歧）
2. **②规则 rules**：`数据源A ⟨算子⟩ 数据源B → 判定档`；同字段不同方向拆多条；每条标 `gate`(闸门·改结论) / `advisory`(提醒·只附建议)
3. **③红线 redlines**：一票否决，`hard_stop` 短路、优先级恒最高
4. **④知识/题库 knowledge**：基准表(主体清单/映射表) + **golden 案例**(输入+正确结论+命中规则)
5. **⑤判断策略 strategy**：四档(通过/预警/驳回/转人工) + 默认档(疑则补·预警) + 聚合规则(最严合并) + 转人工路由

详见 `schema.md`。

## 怎么用（面向业务的三步）

1. **交资料**：按 `questionnaire.md` 把"审什么、红线、四档口径、字段、数据源、参数、边界、已有文档/历史case"能填的填、拿不准写"待定"。
2. **一键提炼**：AI 按 `extract-prompt.md` 的提炼链产出**五件套草稿** + `open_questions`（🟢高置信直接采纳 / 🟡中置信列备选 / 🔴低置信必确认）。
3. **定稿**：只处理黄/红两档 + 对抗自检 + golden 回归全过 → `status:draft` 升 `active` → 进推理内核加载。

## 加载契约（推理内核）

- `load(pack)`：schema 校验 + 引用消解(悬空引用→不可加载) + 建索引 + 跑 golden 冒烟(全过才 loadable)；draft 可加载但带 warnings。
- `execute(handle, evidence)`：redlines(hard_stop)→gate(按 priority)→advisory；按 severity 取最严；advisory 只进 notes；缺数据=兜底档非报错(疑则补)。

## 现状 vs 待建（诚实标注）

- **✅ 设计已定**：四部件 + 五件套 schema + 提炼链 + 加载契约（本目录）。
- **⏳ 待建**：提炼链的可运行 harness、五件套的 JSON Schema 校验器、load/execute 执行器、与现有 `deterministic-checker.js` + `child-judge.md` 两层判断的对接（规则包=外置的团队规则，不可动骨架仍是通用框架，见主报告《多团队复用方案》§六）。
- **首个试点**：**资质自己**（child-judge.md + scenes + 历史审批当输入）——验证工厂能用 + 给资质一份系统化五件套。报销为原设计试点，资料到位后做。
