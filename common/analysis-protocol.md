## 一、步骤 4 三阶段深度审核规格

### 阶段一：证据链核实

**原则**：必须有**外部客观证据**（"被证明"），不能仅凭**申请人自述**（"被说明"）。

| 场景 | 客观证据要求 | 无证据时 |
|------|------------|---------|
| 平台审查 | 露出平台LOGO和要求截图 | 标注"证据不足" |
| 合作审查 | 双章合同 + 合作方具体要求截图 | 标注"证据不足" |
| 诉讼/仲裁 | 律师函/法院通知/仲裁委受理通知 | 标注"证据不足" |
| 劳动仲裁 | 仲裁申请书（调解阶段真实存在） | 可接受为证据 |

**关键区别**：
- "被说明"=申请人在事由里写"平台要求"（主观，不可信）
- "被证明"=有平台截图明确显示要求（客观，可信）

**证据不足 → 标注"证据不足"，不直接驳回。**

**合作/授权类专属：证据链层级**

仅适用于资质类型为「授权书/合同/合作类」的申请。核心判断：业务关系是否真实 + 对方需求是否真实。

**执行顺序**：从上到下逐行检查，找到第一个完全匹配的行即确定基础结论，停止向下。R07 转授权条款检查独立叠加（触发后叠加需补充，不影响层级匹配的基础结论）。退回条件优先于所有层级结论。

| 证据情况 | 结论 |
|---------|------|
| ① 有效双章合同 + ② 对方要求截图 | 直接通过（充分条件） |
| 官方/政府/平台明文要求（P02，须有截图证明，非申请人自述） | 直接通过，不需合同或截图 |
| ① 有效双章合同，无截图 | 需补充：截图——证明对方明确要求提交资质 |
| 往期合同（已过期/待续签）+ ② 截图 | 通过——截图弥补无新合同，证明此次请求真实和必要 |
| 往期合同（已过期/待续签），无截图 | 需补充：截图——历史关系可证明，此次必要性需截图说明 |
| 新合作先提资质 + ② 截图（无合同） | 需补充：双章合同——截图只证明"对方提出了要求"，不证明"合作关系已确立"；公司对外担责须以双章合同为据，无合同不予通过 |
| 无合同（新合作，无历史关系），无截图，无官方要求 | 需补充——业务关系无客观证据，须补双章合同或对方要求截图。缺证据是"材料未齐"（可补），非"造假/根本不成立"，故默认不退回。例外→退回：仅当 ①提供的证明已被识别为伪造，或 ②同一单已补过一轮后仍完全无任何证据（反复空提） |

> ① = 有效双章合同；② = R11字段（对方要求出具资质的截图附件）。
> ⚠️ 「有效」的判断：合同结束日期须晚于今日——过期合同视为往期合同，按第4/5行处理（合同结束时间是否已过今日，须主动核查表单合同明细字段）。
> ⚠️ 缺证据 ≠ 造假：新合作无任何证据默认 → 需补充（给补材料机会）；仅"已证伪造"或"二次仍无证据"才退回。主体/名称存疑、疑似但未证 → 一律需补充，不退回。（第7行默认需补充时照常走阶段二/三；仅命中退回例外闸时可直接定论。）
> ⚠️ **截图一致性核对（F5）**：凡以"截图"作为通过依据的行（第2/4行——官方明文截图证明 / 往期合同+截图弥补无新合同；第6行自 2026-07 起已不再凭截图单独通过），截图里出现的**平台名/对方主体须与本申请的"资质流向方/品牌登记"对得上**；对不上（如截图是 A 平台、流向方却填 B；或截图的对方主体与流向方不一致）→ 不构成有效证据，降为 ⚠️需补充。截图是申请人自备材料，须与申请要素自洽方可采信（这是完整性/一致性核对，不是防伪——默认信任同事上传材料的真实性）。

### 阶段二：逻辑穿透（一次性列缺）

**原则**：AI读取所有信息后，**一次性列出所有缺失项**，不与申请人交互。

**不是**：我问→你答→我再问（效率低）
**而是**：我读→我推→我列（一次性输出到评论）

**四维度检查**：

**看流向（交给谁）**：
| 信息来源 | 有信息时 | 无信息时 |
|---------|---------|---------|
| 相对方字段 | 提取公司名 | 标注"相对方未填" |
| 事由中提到公司 | 提取 | 标注"事由未说明流向" |
| 附件合同甲方 | 提取 | 标注"未读取到合同" |

**看用途（用于什么）**：
| 信息来源 | 有信息时 | 无信息时 |
|---------|---------|---------|
| 平台字段 | 提取平台名 | 标注"使用平台未填" |
| 事由中提到场景 | 提取 | 标注"用途不明确" |
| 附件截图中的LOGO | 确认平台 | 标注"未提供平台截图" |

**业务必要性（为什么要做这件事）**：

必须能从申请事由+附件中回答以下两个问题；答不出哪个就标注哪个缺失：

**Q1 触发条件**：发生了什么业务事件导致这次申请？（"什么事情发生了"，不是"需要什么材料"）
- 例：买家投诉→平台介入举证要求（触发条件清晰）
- 反例：仅写"需要找回账号"（没说为什么要找回）

**Q2 强制必要性**：不做会怎样？是法律/合同/平台强制，还是可以不做？
- 例：法院起诉，不提交资质无法立案（强制性清晰）
- 反例：中信证券开户，"为什么必须开这个户"未说明

**判断标准**：两问都能从现有信息推出 → 通过；答不出任意一问 → 标注缺失项，结论为"需补充"

⚠️ **「推出」的操作定义**（F33：与场景原则"结合背景判断"对齐，消除自相矛盾）：申请事由**或附件证据**中有**明确文字/客观内容**能直接回答该问，即视为"推出"——**附件背景里的明确要求也算"明确文字"**（如平台截图上显示的举证要求、合同条款里的约定），可据以推出，这正是 P01"短事由 + 充分背景附件可通过"的依据。禁止的只是**毫无任何文字/证据支撑的纯脑补**（"从场景凭空推测"/"我觉得合理"）：事由无文字、附件也无证据 = 答不出 = 需补充。判别口诀：**有据可依（事由或附件原文）= 推出；无据臆测 = 脑补。**

⚠️ 场景原则优先：L01（仲裁/诉讼）、P02（平台强制要求）等场景下，业务必要性已由场景原则覆盖，不需重复审查。

**主体必要性（为什么必须是公司/法定代表人）**：

核心问：有没有法律规定/合同约定/平台强制，要求必须是公司/法定代表人出面？（还是说，内部可以授权给员工或代理人处理？）

检查路径：
- 法律强制：诉讼/仲裁/工商等场景，法定代表人是法律规定主体 → 主体必要性成立
- 合同约定：合同条款明确指定法人签字/盖章 → 主体必要性成立
- 平台强制：平台要求企业身份验证/法人认证 → 主体必要性成立（P02原则适用）
- 以上均无：标注"未说明主体必要性" → **结论为需补充**，申请人应说明为何必须法人出面

⚠️ 三维度不重叠：业务必要性（为什么做这件事）/ 主体必要性（为什么必须法人）/ 替代控制（能否用更轻量的材料形式）

**无证据时的处理**：
- ❌ 不脑补
- ❌ 不推断"我觉得合理"
- ✅ 标注"无法从现有信息确认"

### 阶段三：风险控制（硬标准）

审材料时就要检查，包含三部分：

**1. 替代控制**

材料形式证据检查（先查，再建议）：
- 查平台截图/合同条款/表单字段，确认对方要求的最低材料标准
- 有明确要求"必须原件/签字"的 → 已证实最低要求，不追问替代方案
- 无明确要求 → 在💧建议中提出可否用复印件/扫描件/章替代

| 资质类型 | 追问/建议 |
|---------|---------|
| 法人身份证 | 对方是否接受复印件？ |
| 法人签字 | 对方是否接受法人章替代签字？ |
| 原件 | 对方是否接受扫描件？ |
| 授权书 | 能否缩小授权范围（限平台/限时间）？ |

⚠️ **替代控制不影响结论**：有改善空间 → 输出"💧建议：..."，结论照给；无可优化项 → 不需特别说明。

**2. 限制控制**

❌ **退回条件**（触碰→退回）：
- 凭证有造假迹象（含查无业务关系：申请人声称有合作但提供的证明被识别为伪造）

⚠️ **需补充条件**（触碰→需补充，有可操作的补充路径）：
- 品牌/商标授权书含转授权/再授权/可授权他人条款 → 须提供修订版授权书（明确删除该条款）
- 授权范围不明确 → 须补充明确授权范围
- 授权期限不受控 → 须补充合同明细中的开始/结束时间

🔢 **授权书数值边界（品牌/商标授权书·强制逐项核对，2026-07-04 新增，源自知识库）**——从授权书文档读出下列值，与合同/表单逐项比对，任一越界→需补充（这些值在授权书正文里，须实际读出，不得凭空假设）：
- **【平台场景专属】授权时间 ≤ 3 年**：仅当合作方=平台时；授权期限 > 3 年 → 需补充。非平台合作方按合同期限，不套 3 年（勿丢"平台"主语）。
- **授权日期 ≤ 合同合作期限**：授权书的授权起止 须落在合同的合作期限内；超出 → 需补充。🔵**合同期限已代码预解析**：case 的 `deterministic.contract_date_range`（`{start,end,expired}`，从「合同明细」抽出）非 null 时【直接用它当合同合作期限】去比授权书日期，不用自己再从文本找；`expired=true` 表示合同已过期（结合续签/对方确认再判，不自动通过）。为 null（合同明细没写可解析区间）时，回退读合同附件正文自行判定。
- **门店数量 ≤ 合同门店明细 + 稽查审批之和**：授权书门店数 > 合同门店明细 → 需补充。
- **授权地区/渠道/系统 ⊆ 合同**：授权书的地区/渠道/系统 须被合同包含；超出 → 需补充。
> 读不到授权书正文（无授权书本体/needs_vision 未识别）时，标注"授权书数值边界未核"并按缺件/证据不足处理，不得默认通过。

📑 **新项目决策文档·四要素强制审核（2026-07-04 新增，源自知识库；表单「是否为新项目=是」已强制上传附件）**——新项目/项目申请，除有决策文档附件外，AI 须**逐项审文档内容能否清晰回答以下四要素，缺任一→需补充**：
- **需求方**：品牌 / 部门是谁？
- **价值**：效率（减流程/提速）、效果（质量/竞争力）、效益（投产比/性价比）、长期价值——是否说清？
- **必要性**：最优解（为什么是它）、唯一解（为什么一定要它）？
- **风险**：各环节、长短期风险是否评估？
> 「是否为新项目=是」但无决策文档附件 → 需补充（表单应已拦截，此为兜底）；有附件但四要素不全 → 需补充，指出缺哪项。

⚠️ **风险提醒**（标注→可通过，以💧建议输出）：
- 无撤销权条款
- 原件脱离控制
- 单独交业务人员

**3. 技术控制**
- AI给出**不超过15字**的水印建议
- 例："限用于拼多多WIS官旗认证"
- ⚠️ 技术控制不影响结论，以💧建议附在通过结论后输出

## 二、结论判定标准（防过度转人工）

- 🧠 **判断全部由你(大模型)做；OCR/工具只提供信息**（text / segments / score / status / 确定性红线结果），**绝不替你下结论**。"转人工"也是你的判断，不是 OCR 判的。
- ⚠️ **结论优先级**：退回条件一旦触发，优先于需补充条件，最终结论=退回；不得因同时存在可补充的缺失项而将退回降级为需补充。
- ⚖️ **"疑则补"默认原则（2026-07 新增）**：证据/信息不足时，"需补充"是默认档。退回仅用于「已证造假 / 逻辑已能明确判定根本不成立 / 明确不该担责 / 同一单二次仍无证据」；转人工仅用于「全部附件失败且表单也不足以判方向」。**不确定但可补、疑似但未证 → 一律需补充，绝不轻易退回或转人工。**
- **四档结论**：
  - ✅ **通过**：阶段二（逻辑穿透）满足 + 未触发退回条件。替代控制/技术控制有改善空间不影响通过，以💧建议附在结论后输出。
  - ❌ **退回**：凭证有造假迹象（申请人声称有合作但提供的证明被识别为伪造）；或 逻辑上已能明确判定根本不成立/明确不该由公司担责；或 合作/授权类新合作二次仍无任何证据（见证据链层级第7行例外闸）。**"缺证据/材料未齐/主体对不上但可补/疑似存疑"都不是退回理由——那是"需补充"。**
  - ⚠️ **需补充**：阶段二（逻辑穿透）不满足；或 合作/授权类【新合作仅有对方要求截图、无双章合同】（阶段一证据链层级第6行：截图证明对方请求属实，但公司对外担责须有双章合同为据）；或 品牌/商标授权书含转授权条款（须提供修订版授权书）；或 授权范围不明确/期限不受控。附件读取失败（`status≠ok`）时，**跳过失败附件**，仅基于可读信息评估：可读信息已覆盖四维度 → 结论照给，评论标注所有失败附件（文件名 + 原因 + "需人工核查原件"）；可读信息不足某维度 → ⚠️需补充，标注具体缺失维度 + 所有失败附件。**"需补充"的原因是信息不足，不是附件失败本身。**
  - 📄 **截断读附件（`truncated_pages=true`，大扫描件只渲染了前 N 页交视觉）**：若判断四维度所需的**关键证据已在已读页确认**（如商标注册证的证号/主体在首页）→ 结论照给，评论注明"仅审前 N 页，其余页需人工核对原件"；若**关键证据可能在未读页**（已读页未见所需的证号/主体/印鉴/金额/关键条款）→ 结论偏保守（⚠️需补充 / 🔴需人工核原件），**绝不得凭截断证据给通过**。同理见 `attachments_summary[].truncated_pages` 与顶层 `truncated_attachments`。
  - 🔴 **转人工**：**仅当全部附件均读取失败**且表单信息又不足以做出任何判断时，才给 🔴转人工。`low_conf`/`min_score` **仅参考，绝不因它转人工**。
- 🚫 **操作性细节不升级**：用印类型(法人章/财务专用章)、份数、措辞这类**执行细节**，写"💧建议/提醒"，**结论照给**，绝不因此转人工或退回。
- 核心原则：**审核评的是"公司该不该为这件事担责"，不是"每个细节都 100% 确定"。** 拿不准的细节是**备注**，不是闸门；闸门只留给**红线**和**根本看不到证据**。
- 🚧 **审核边界（负向规则·什么不该管，2026-07-04 新增）**：审核只判"公司该不该为这件事对外担责/出这份材料"，**不替公司做商业决策**。具体边界：
  - **内部主体/部门之间无需授权、无需澄清关系**——流向方/申请部门若是凡岛内部主体或部门（见 `entities.json` internal_entities / overseas_entities / departments，含总经办各子中心、凡岛研究院等），不得当外部主体要求澄清；内部授权是唯一可直接通过项。
  - **外部金融产品的风险等级（如证券业 R1–R5）≠ 审核阻断理由**——那是产品有多险的外部事实，不是"该不该批"的标准；技能包自有"风险等级"是高/中/低的资质敏感度，也仅供严格度参考、不阻断。
  - **"法人已决策"属【需被证明】的事实**：须有决策截图/决策文件佐证方可采信；若仅业务口头声称（被说明）、无证明，**不能据此认定必要性成立**，须继续审核/追问。不得凭"法人已决策"越权替公司判断该投资/该业务本身该不该做，但也不得凭口头"已决策"就放行——**要证明**。
- 补充建议 = 非必需的优化建议；禁止：既说"合理"又说"有风险"而不解释关系；禁止简化版替代完整三阶段。

## 三、分析一致性保障（附录A）

### 问题：评论不一致
**症状**：同一审批实例有多个AI评论，结论互相冲突（如第一次说"✅通过"，第二次说"❌退回"）。

**根因**：
1. 第一次用完整三阶段判断（agent 大模型，读 SKILL.md+references）
2. 第二次用简化版/快速规则（关键词、临时脚本或手动判断）
3. 两套逻辑标准不同 → 结论不同

**解决方案**：
1. **同一审批只写一次评论** — `audit-tool.cjs comment` 内 `hasAIComment()` 检测到已有评论则跳过
2. **必须修正时写统一版** — 追加"统一版"评论，说明冲突原因，基于完整分析重新确认
3. **绝对禁止简化版** — 任何审核/重审都必须由 agent 用完整三阶段判断，**不得退回关键词或简化规则**
4. **工具自检** — `comment` 子命令写入前检查已有评论数量，发现冲突由 agent 写统一版

### 错误降级策略

| 失败场景 | 降级行为 | 输出标注 |
|----------|---------|---------|
| 表单解析失败 | 尝试备用解析方案（逐段JSON解析） | "表单读取异常，建议人工查看" |
| 字段名不匹配 | 遍历所有字段，模糊匹配 | "字段名不标准，已尝试模糊匹配" |
| 附件下载失败 | 基于表单字段做初步分析 | "附件未下载，结论基于表单字段" |
| 附件读取失败 | 尝试3种方案后仍失败 | "附件读取异常，最终结论需人工确认" |
| API超时 | 记录到日志，标记为待重试 | "API超时，将自动重试" |
| 评论区读取失败 | 忽略评论区，继续主流程 | "评论区未读取" |

**核心原则**：降级≠停止，降级后仍应给出尽可能完整的分析，但**必须明确标注不确定性来源**。
